# 架构决策记录（ADR）

## ADR-001：模型推理一律外部 API 接入（2026-09-06，用户拍板）

**背景**：早期调研文档按"自部署 = 本地 GPU 直接跑模型"写选型（docs/features 各篇的"自部署复刻选型"章节）。

**决策**：自部署仅指本软件本身。模型推理一律以外部 HTTP API 方式接入：
- 远程云 API（OpenAI images 兼容协议等）
- 本地推理服务（ComfyUI API 等）——对软件而言同样是外部 HTTP 服务

**约束**：仓库代码永不出现模型权重下载/加载/本地推理。调研文档中与"本地 GPU 推理选型"相关章节视为历史参考，以 CLAUDE.md 铁律为准；其中的官方参数契约、CLI 源码证据章节仍然有效。

**推论**：Provider 适配层是核心抽象；ComfyUI 生态尽可能复用（workflow 模板走其 API），不重复造轮子。

## ADR-002：P1 任务存储用文件系统（2026-09-06）

**决策**：任务元数据 `data/jobs/<job_id>/job.json`，产物 `data/artifacts/<job_id>/`（媒体文件 + `final_outputs.json`），写入用临时文件 + rename 原子写。与原版官方"任务子目录 + final_outputs.json"产物形态对齐。

**推论**：单用户自用场景下无并发竞争问题，P1 不引入数据库；存储接口留抽象，P5+ 若需队列管理再换 SQLite。

## ADR-003：曳光弹开发法（2026-09-06，用户拍板）

**决策**：P1 用文生图一条竖切从 0 到 1 打通整体架构（API→任务→Provider→产物），验证 Provider 适配层、异步任务模型、产物契约三支柱。后续能力域全部横向扩展：新 Provider + 新路由，不动骨架。

**流程**：代码开发统一走 Claude Code；每批任务结束自我审查（pytest/ruff/铁律检查），偏离就停。

## ADR-004：参考库功能砍掉（2026-09-07，用户拍板）

**决策**：不复刻原版的 1000+ 内置参考库（地图/纹理参考检索下载）。理由：官方预设来源与版权状态未知（open-questions 台账），自部署引入有合规风险；单用户自用场景下价值有限。

**推论**：05 篇调研中"预览服务 + 参考库 CLI 是产品体验一半"的部分只保留预览服务思路，参考库相关能力域从 ROADMAP 移除。

## ADR-005：L5 真实冒烟走 pollinations（2026-09-07，用户确认无 OpenAI 兼容生图端点）

**决策**：用户当前只有 LLM API、无生图 API；pollinations.ai 实测可用（免 key、GET /prompt 直连、seed 确定性），新增 pollinations Provider（第三后端）用于 P1 端到端真实冒烟。openai_compat 保留，待用户将来提供 OpenAI 兼容生图端点后即插即用。

**边界**：pollinations 定位是临时冒烟通道（无 key 档延迟 6-45s 波动、模型服务端路由不可控），不作为正式能力域的推荐后端；正式后端 = ComfyUI（本地）+ openai_compat（云）。
